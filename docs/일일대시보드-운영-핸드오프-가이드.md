## 3. 생성 파이프라인

생성기: **`tools/dashboard/generate_dashboard.py`** (이 한 파일이 모든 로직·규칙의 단일 소스).

```bash
cd "<repo>/dashboard"
set -a && source ~/.config/atlassian.env && set +a          # Jira 자격증명
export JIRA_EMAIL="$ATLASSIAN_EMAIL" JIRA_API_TOKEN="$ATLASSIAN_API_TOKEN" JIRA_BASE_URL="${ATLASSIAN_SITE:-https://platfos.atlassian.net}"
python3 tools/dashboard/generate_dashboard.py --date 2026-06-17 --write-cache
```

- 데이터 소스: Jira REST **`/rest/api/3/search/jql`** (POST, nextPageToken 페이지네이션). 구 `/search`는 410 Gone.
- JQL: `project = PG AND status NOT IN (완료, Done, 후속작업, 보류)` — **보류·완료 자동 제외**.
- 템플릿 골격: `Source/대시보드/platfos_dashboard_260604_원본.html`.
- 캐시(변경이력 diff 기준): `public/data/.cache/platfos_dashboard_latest.json` = "직전 스냅샷".
  - `--write-cache`는 생성 후 캐시를 오늘로 전진 → **하루 1회만**. 같은 날 재생성 시엔 직전 영업일 커밋에서 캐시 복원 후 실행(안 그러면 변경이력이 빔).

## 5. 일일 생성 절차 (요약)

1. repo 이동 → `git stash push -- .gitignore` → `git fetch origin` → `git merge --ff-only origin/main` (자동화가 앞서 있을 수 있음).
2. 캐시 baseline = 직전 영업일인지 확인(같은 날 재생성이면 직전 커밋에서 복원).
3. 생성기 실행(§3, `--write-cache`).
4. 검증(§4 불변식 전부) — 이강미/김 가영/jason = 0, 정광희 카드 제외, 진행중 합계 라이브 일치.
5. `git add` 산출물(+캐시) → 커밋(Co-Authored-By 푸터) → `git push origin main`.
   - push 거부 시: `git fetch` → `git rebase origin/main` → 충돌난 .html/.cache는 **캐시 복원 후 재생성**으로 해결 → `git rebase --continue` → 재push.
6. `git stash pop`.

> Claude Code 사용 시: 위 절차는 스킬 **`daily-dashboard-output`**(`.claude/skills/`)에 캡슐화돼 있어 "아웃풋 만들어줘"로 트리거된다.

## 6. 자주 겪는 함정 (Gotchas)

- **자동화가 수동 commit을 덮어쓴다**: 별도 자동화가 `chore: generate Platfos dashboard`로 같은 날짜를 재생성·push함 → push 전 항상 fetch/rebase, 충돌 시 재생성으로 해결. 생성기(.py) 수정은 자동화가 안 건드리므로 다음 자동 실행부터 반영됨.
- **한글 `\u` 이스케이프**: 템플릿 JS 상수에 한글이 `\uXXXX`로 박혀 있어 리터럴 `grep "이강미"`/replace가 못 잡았던 사례 있음 → 검증 시 `\uXXXX` 형태도 확인하거나 생성기 주입으로 해결.
- **정적 하드코딩 잔재**: 템플릿(06-04 기준)에 손으로 쓴 정적 값/카드가 많았음(상태 합계·멤버 카드·이강미 등). 새로 "숫자가 안 맞는다"는 제보가 오면 **그 부분이 생성기에서 동적 주입되는지** 먼저 의심.
- **히트맵 셀 표시**: WS_HEATMAP 셀은 `total`(전체 카운트)과 `issues`(표시용 샘플 ~8개) 분리. 키가 목록에 없어도 total엔 포함될 수 있음 → 카운트는 total 기준.
- **bespoke 미동적 잔재**: 실행상황판의 "최종 점수 64점"·"PG-3081 잔존" 등 일부 스코어 요소는 아직 정적(상태/담당자 집계와 무관).

## 8. 규칙 바꾸는 법

전부 `tools/dashboard/generate_dashboard.py` 한 파일에서:
- 새 퇴사자/이름변경 → `normalize_owner()`에 한 줄.
- 팀원 추가/이동 → `TEAM_MEMBERS`/`PLAN_TEAM`/`DEV_TEAM`.
- 특정인 카드만 숨김 → `STATUS_CARD_HIDE`.
- 시퀀스 추론 키워드 → `seq_for_issue` 규칙(단, 제목 `[S#]` 규칙이 우선·신뢰도 높음).

수정 후 §5 절차로 재생성·배포하면 그날부터(그리고 자동 생성에도) 반영된다.
